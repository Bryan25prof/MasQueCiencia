MQC — LOTE PREVIO DE INTEGRIDAD (previo a la migración XP 2.0)
================================================================

Qué es este paquete
--------------------
Es la Parte A del "lote previo de integridad" que pediste antes de
autorizar la migración XP 2.0: la corrección de un bug real de
farmeo de XP en el Proyecto Integrador Final ("Alerta en el Río
Pacuare").

El bug: cada una de las 7 estaciones del proyecto otorgaba sus 30 XP
sin ninguna guarda persistida. El único camino de regreso del flujo
("← Revisar el caso", en la pantalla final) llevaba de nuevo a la
estación 7, y su botón "Continuar" volvía a otorgar los 30 XP cada
vez — de forma indefinida, con un botón real de la interfaz, sin
necesidad de herramientas de desarrollador ni trucos. Confirmado con
una prueba funcional real (no solo lectura de código): se repitió el
ciclo dos veces y ambas veces se otorgaron 30 XP de más.

La corrección es puramente ADITIVA:
- Se agrega una guarda nueva ("estacionesPremiadas") dentro del mismo
  objeto que ya se guardaba para este módulo (junto a "completado",
  "informe", "xpAwarded" — mismo patrón, ninguna estructura nueva en
  Storage).
- No se borra ninguna respuesta del estudiante.
- No se cambia el significado de "completado" (los 300 XP del informe
  final siguen otorgándose exactamente igual que antes, con su propia
  guarda intacta).
- No se resta XP a nadie ni se modifica ningún perfil existente: un
  perfil que ya había completado el proyecto antes de este fix
  simplemente ya no tiene ocasión de volver a recibir XP de estación
  después de completado (eso se infiere de "completado:true", sin
  escribir nada retroactivo en su perfil).

Verificado con 3 pruebas funcionales automatizadas (detalle completo
en MQC_LOTE_PREINTEGRIDAD_XP2_REPORTE.md):
  A) La secuencia exacta que pediste: primera finalización de la
     estación 7 → +30 XP · "Revisar el caso" → "Continuar" → +0 ·
     repetir de nuevo → +0.
  B) Un perfil nuevo puede obtener exactamente una vez los 30 XP de
     CADA una de las 7 estaciones, y el informe final sigue otorgando
     sus 300 XP con su guarda original intacta.
  C) Un perfil YA EXISTENTE (que ya tenía el proyecto completado antes
     de este fix, sin la guarda nueva) queda protegido igual, sin
     necesitar ninguna migración escrita sobre su perfil.

Archivo incluido (1), con su ruta EXACTA dentro del repo:

    js/modules/integrador.js

Cómo subirlo a GitHub
----------------------
1. Descomprimí este .zip en cualquier carpeta temporal. Vas a ver una
   carpeta "MasQueCiencia_Beta_v1.0/" con la misma estructura de
   subcarpetas que tu repo.

2. Copiá el archivo a la misma ruta dentro de tu copia local del
   repo:
   - js/modules/integrador.js   → REEMPLAZA el que ya existe

3. Confirmá el cambio con git y subilo a GitHub, por ejemplo:

     git add js/modules/integrador.js
     git commit -m "Lote previo de integridad XP 2.0: guarda persistida por estacion en Proyecto Integrador"
     git push

Qué vas a notar distinto
--------------------------
Nada distinto en la experiencia normal de completar el proyecto una
sola vez. La única diferencia observable es que "Revisar el caso" ya
no vuelve a otorgar los 30 XP de la estación 7 (ni de ninguna otra) si
se repite el flujo.
